คู่มือการทำงานของระบบและสถาปัตยกรรม (System Workflow Manual)

ระบบคลังรวมและเผยแพร่โครงงานวิจัย บัณฑิตศึกษาและโปรเจกต์จบ มหาวิทยาลัยราชภัฏสุรินทร์
Architecture & Workflow Guide
🏛️ 1. ภาพรวมสถาปัตยกรรมการทำงาน 4 ชั้น (4-Tier System Architecture)

ระบบถูกออกแบบด้วยสถาปัตยกรรม Decoupled Client-Server & AI Micro-Engine โดยแบ่งการทำงานออกเป็น 4 ชั้นหลัก เพื่อประสิทธิภาพ ความปลอดภัย และความสามารถในการประมวลผลภาษาไทย:

1. Frontend Layer Vue.js 3 + Vite
TailwindCSS UI
Pinia State Stores
PDF Reader & Annotation
2. API & Server Layer Node.js + Express.js
JWT Auth & RBAC
RESTful API Routing
Multer PDF Storage
3. AI & NLP Engine PyThaiNLP Tokenizer
TF-IDF Vector Space
Cosine Similarity
On-Premise RAG Engine
4. Data & Persistence MySQL 8.0 (InnoDB)
User Interaction Logs
Recommendation Cache
PDF Files (/uploads)
🔄 2. ขั้นตอนการทำงานแบบสมบูรณ์ 3 บทบาท (End-to-End User Workflows)
👨‍🎓 ก. ขั้นตอนการทำงานของนักศึกษา (Student Flow)
1ค้นคว้าและหาไอเดีย: ใช้งาน AI Topic Generator สังเคราะห์ 3 โครงร่างวิจัยตามโจทย์ที่สนใจ และสืบค้นงานวิจัยรุ่นพี่ด้วย Semantic Search
2เจาะลึกเล่มวิจัย: เปิดอ่านไฟล์ PDF และใช้งาน AI Chat with PDF (RAG) พิมพ์ถามระเบียบวิธีวิจัยและสถิติ ระบบจะดึงคำตอบพร้อมชี้เลขหน้าอ้างอิงทันที
3ตรวจสอบความซ้ำซ้อน: ในหน้าส่งงานวิจัย พิมพ์ชื่อเรื่องและบทคัดย่อ ระบบ Redundancy Radar จะคำนวณเปอร์เซ็นต์ความซ้ำซ้อนแบบเรียลไทม์ และพิมพ์ใบรับรอง Originality Certificate
4ส่งเอกสารฉบับสมบูรณ์: แนบไฟล์ PDF เล่มวิจัยจริง สถานะจะขึ้นเป็น 🟡 รอการตรวจสอบ (PENDING) เพื่อส่งต่อให้อาจารย์ที่ปรึกษา
👩‍🏫 ข. ขั้นตอนการทำงานของอาจารย์ผู้ตรวจ (Teacher Reviewer Flow)
1รับแจ้งเตือน: เข้าสู่ระบบ Teacher Portal พบรายการงานวิจัยของนักศึกษาที่รอตรวจประเมิน
2ตรวจแก้งานบน PDF: เปิดดูไฟล์ PDF ในเบราว์เซอร์ พร้อมใช้ฟังก์ชัน Academic Annotation ไฮไลต์ข้อความและพิมพ์บันทึกข้อคิดเห็นลงบนหน้าเอกสาร
3ตัดสินใจประเมิน: เลือก 🟢 อนุมัติ (APPROVE) เพื่อเผยแพร่สู่สาธารณะ หรือ 🔴 ส่งกลับแก้ไข (REQUEST CHANGES) พร้อมระบุเหตุผลเพื่อให้นักศึกษานำไปปรับปรุง
👑 ค. ขั้นตอนการทำงานของผู้บริหารและแอดมิน (Executive & Admin Flow)
1ตรวจดูภาพรวม: เปิด Executive Dashboard ตรวจสอบตัวชี้วัด KPI 4 มิติ และสัดส่วนผลงานวิจัยรายคณะ
2คาดการณ์แนวโน้ม: ดู Research Trend Forecasting เพื่อวิเคราะห์ทิศทางงานวิจัยที่ตอบโจทย์จังหวัดสุรินทร์
3ส่งออกข้อมูล: กดปุ่ม Export เพื่อนำข้อมูลสถิติออกเป็นไฟล์ Excel/CSV สำหรับใช้ประกอบการจัดสรรงบประมาณ

AI Engine & Evaluation
🧠 3. กลไกการประมวลผล AI & โมเดลระบบแนะนำ (AI Pipeline Workflow)
1. Thai NLP Preprocessing & TF-IDF (60%)

• ข้อความภาษาไทย (ชื่อเรื่อง, บทคัดย่อ) ถูกตัดคำด้วย PyThaiNLP (engine newmm)
• กำจัดคำเชื่อม/คำหยุด (Stopwords Removal)
• สร้างเวกเตอร์ความถี่คำ TF-IDF และคำนวณ Cosine Similarity เพื่อจับคู่ความคล้ายคลึงของเนื้อหา

2. Collaborative Interaction Matrix (40%)

• บันทึกพฤติกรรมผู้ใช้ลงในตาราง user_logs
• ถ่วงน้ำหนักความสนใจ:
  - Bookmark = 3.0 คะแนน
  - Download = 2.0 คะแนน
  - View = 1.0 คะแนน
• นำมารวมกันเป็นสูตร: Final Score = 0.6 CB + 0.4 CF

3. กระบวนการทำงานของระบบ RAG (Retrieval-Augmented Generation)
ขั้นที่ 1: Text Ingestion สกัดข้อความจาก PDF
แบ่งประโยคเป็น Semantic Chunks
ขั้นที่ 2: Intent Matching จำแนกคำถามของผู้ใช้
วิ่งไปค้น Chunks ที่ตรงใน PDF
ขั้นที่ 3: Answer Synthesis สรุปคำตอบเป็นภาษาไทย
แนบเลขหน้าอ้างอิงชัดเจน
🗄️ 4. สรุปความสัมพันธ์ของฐานข้อมูล 7 ตารางหลัก (Entity Relationships)
ตาราง (Table) ฟิลด์สำคัญ (Key Fields) ความสัมพันธ์ (Relation) บทบาทในการทำงานของระบบ
faculties / departments faculty_id, department_id, name 1:N (คณะแตกเป็นหลายสาขา) โครงสร้างสังกัดทั้ง 7 คณะของ มรภ.สุรินทร์
users user_id, email, password_hash, role FK ไปยังคณะ/สาขา ระบบระบุตัวตนและ RBAC (STUDENT / TEACHER / ADMIN)
research_projects project_id, title_th, abstract, status, pdf FK ไปยังผู้ส่ง/ผู้อนุมัติ ศูนย์กลางจัดเก็บงานวิจัย มี Full-text Index ค้นหาเร็ว
user_bookmarks bookmark_id, user_id, project_id N:M (ผู้ใช้กับเล่มวิจัย) ระบบบันทึกงานที่สนใจเพื่อเปิดอ่านภายหลัง
user_logs log_id, action_type, project_id, timestamp FK ไปยัง users & projects บันทึกพฤติกรรมจริงเพื่อใช้คำนวณ Collaborative Filtering
recommendation_cache cache_id, user_id, project_id, score UNIQUE (user, project, algo) แคชผลแนะนำล่วงหน้า โหลดหน้าแรกไวภายใน 0.05 วินาที
